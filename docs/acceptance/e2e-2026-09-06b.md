## Rig

Two rig facts that shape every row below. Neither is a product defect.

1. The `windows-dtry` MCP returns `No windows found` and `No active window found`
   for every window on dtry, on every call, while its `Screenshot` and its input
   injection both work.
   So `App mode=switch`, `App mode=resize`, `WaitFor` on a window name and every
   label-based `Click` are unusable in this session.
   Input and window control run instead through a `schtasks /it` task in session 1
   (`surya-e2e2-run`) driving `SendInput`, and frames are taken with `BitBlt` of
   the app's client rectangle after the window is brought to the front.
2. I use `ssh dtry` to move frames off the box, to read
   `E:\surya-e2e2-data\logs\surya-headed.log`, and to read
   `E:\surya-e2e2-data\ui-settings.json`.
   The MCP cannot reach files. The brief allows this and asks that it be said here.

A third rig note, recorded because it wasted time and would waste anyone else's.
`MoveWindow` and `SetWindowPos` against the surya window always force the height
to 1460 px, whatever height is asked for, while honouring the width.
A mouse drag on the same window edge resizes it correctly to any size down to the
minimum. So programmatic resize is not a usable measurement and every size in this
record was set by dragging the window border with injected mouse input.

## Findings

### E2E-WIN-01 (design) - the app window has no name anywhere outside itself

Repro: start the app, then from session 1 run
`Get-Process surya | Select-Object MainWindowTitle`.

- expected: a title, so the taskbar, Alt+Tab, window switchers and screen readers can name the window.
- seen: `MainWindowTitle` is empty; the window class is `Zed::Window`. The text `luvus @ pc-ajim` is drawn inside the client area only.

Frame: `01-launch-first-frame-dark.png` (the drawn title bar), and the empty
`ostitle=[]` in every window probe in this record.

The owner's own running build shows the same, so this is not new to the rename.

### E2E-WIN-02 (design) - window size and position are thrown away on every restart

Repro: resize the window with the mouse, move it, close it with the X button,
start it again.

- expected: the window comes back where and how it was left, as comet and every other desktop app do.
- seen: closed at 1094x1447 at (52,0); reopened at 1336x888 at (1052,276). Four launches in a row landed on the same 1336x888 default.

`E:\surya-e2e2-data\ui-settings.json` stores `sidebarWidth`, `rightPaneWidth`,
`terminalHeight` and the keymap, but holds no window bounds at all.

Frames: `01-window-1100x700-dark.png` (before the close), `01-relaunch-state-dark.png` (after).

### E2E-UI-01 (design) - the session title is not aligned with the transcript it belongs to

- seen: the title and breadcrumb are pinned to the left of the pane while the transcript and composer sit in a centred column about 740 px wide. At a 1904 px client the two left edges are 439 px apart; maximised at 3440 px they are about 1200 px apart, with the title alone on the far left of an empty band.

### E2E-KEY-01 (bug) - every keyboard shortcut dies while the Needs you page is open

Repro, from a session view:

1. Press Ctrl+Shift+T. The Tasks pane opens.
2. Press Ctrl+Shift+F. The Files pane opens.
3. Press Ctrl+Shift+I. The Needs you page opens.
4. Press Ctrl+Shift+T again, then Ctrl+J.

- expected: the Tasks pane toggles, then the terminal toggles.
- seen: nothing. Steps 4 and 5 produce byte-identical frames (md5 `e85bec72` for all three of `02-chord-c-inbox-dark.png`, `02-chord-d-tasks-from-inbox-dark.png`, `02-chord-e-terminal-dark.png`). Clicking Home with the mouse revives every shortcut immediately.

Confirmed a second time in isolation: two chords on the Needs you page gave one
identical frame (`eca2caa0` twice), one mouse click on Home changed the frame,
and the next chord worked again.

The window is the foreground window throughout, and plain typing into the
composer works, so this is not focus loss at the OS level.

Frames: `02-shortcut-dead-on-inbox-1-dark.png`, `02-shortcut-dead-on-inbox-2-dark.png`, `02-shortcut-after-home-click-dark.png`, `02-shortcut-alive-again-dark.png`.
