## Known issues

Two lists. The first is what will get in your way. The second is what looks wrong but costs you nothing. The numbered list further down is the engineering record and it goes back to the earlier candidates.

### Fixed since the sweep

The tester found these and they are already fixed in the build you have.

| Was | Now |
|---|---|
| Clicking the browser address bar did not select the URL, so typing added to the end of the old address | A click selects it. Typing replaces it. |
| Clicking a pane tab dragged it instead of opening it | A click on Browser, Files or Tasks opens that tab. Hold the tab down for a moment and drag to reorder. |

### Things that will bite you

| Issue | What it means for you |
|---|---|
| The browser pane on Windows runs web pages with the Chromium sandbox OFF | A page runs with your own user privileges. Linux has the sandbox on. Treat the pane as a browser with its protections removed and do not open sites you do not trust. The fix is the first browser job after the RC. |
| Chats on a non-Claude harness never ask permission | Only Claude Code chats have the permission gate. A chat started on Codex, Cursor, OpenCode or an ACP agent runs every action unattended. Stay on Claude until this is fixed after the RC. |
| A real agent cannot draw a card | Ask for one and you get a plain table. The agent is never given the card tool on a real run, so it has nothing to draw with. The renderer itself is fine. A fix is in review. |
| Keyboard shortcuts stop working while Needs you is open | Every one of them. Click Home and they come back. |
| Two paths still throw unsaved edits away | Reloading a file from disk, and switching space. The file-to-file case is fixed. Both are after the RC. |
| "Always allow in this project" allows one file only | The next file asks again. |
| Escape on a permission card denies the request | While the agent is asking permission, the card replaces the composer, and pressing Escape answers Deny rather than closing the card. The card does say "Esc denies", but Escape closes things everywhere else in the app. Answer with the buttons. |
| A turn that fails cannot be re-run | There is no retry control. You can send the message again, which is what comet offers. |
| Stopping a run leaves no mark in the transcript | Nothing says the answer was cut short. |
| The docked Tasks pane shows only two of its four columns | Done is cut off and Blocked never appears. There is no scrollbar and widening the pane does not help. Use the expand control in the tab strip to see all four. |
| The New project folder search only looks at what it has already loaded | In a big directory the folder you want may not appear. Scroll to it first. |
| Ctrl+Enter in the folder picker adds the folder you are browsing | Not the one you highlighted. Press the right arrow to go into a folder first. |
| A second copy of surya on the same PC says "Browser off" | The first copy holds the browser cache and nothing explains that. Close the first one. |
| Restarting the engine drops the app on an error screen | An ordinary engine upgrade takes about ten seconds, and the app sits on the error screen until you press Retry. It does not come back on its own. |
| Subagents all show as "Untitled chat" in the tree | The dot colour is the only thing telling them apart, so more than two running at once cannot be told apart at all. |
| Card buttons on a finished run do nothing | No change, no message. Only buttons on a live run act. |
| The window forgets its size and position | Every restart puts it back at the default. |
| The unsaved-edits prompt has no keyboard path | You have to click Save, Discard or Keep editing. |
| The Agents entry on the rail does nothing you can see | It is not broken code. Nobody has designed what that page shows. Your call. |
| Ctrl+S saves in the editor, and still toggles the sidebar everywhere else | That is the shipped default. Moving the sidebar toggle to another key is your call. |

The sandbox detail, for whoever picks it up: Linux uses a SUID helper. Windows needs `cef_sandbox` linked at build time plus two call sites.

0. FIXED in RC2 (PR #74): a saved server that cannot be reached (the owner's port-22 typo, 13:00) no longer locks the app; the Failed gate offers "Use this computer" and "Fix the server...", the Add-server default port is 27700, and surya.cmd quotes the exe path. GitHub-hosted CI died on account billing at 12:35; CI runs on a self-hosted runner on pc-ajim (decision 24).

1. Windows renderer drops filled quads per frame (buttons, underlines, checkbox fills flicker). ROOT CAUSE FOUND 11:26 (PR #54): the gpui fork added a 32-byte fade field to Quad and PolychromeSprite and updated the Metal and WGSL shaders but not `shaders.hlsl`, so the DirectX stride is 192 bytes against a 160-byte shader layout and every quad after the first in a batch reads the wrong offset. FIXED in RC1 (PR #56 repin to screamyx/gpui-surya): dropped quads 0 across 7 frames on the Windows box (PR #66).
2. The browser pane ships in the Windows zip since PR #73 (owner ruling 13:10, decision 25): `build.ps1 -Browser` packages CEF 151.3.24 beside the exe, a fresh-folder launch painted example.com on dtry. The CEF crate is still excluded from CI (1.4 GB artifact), so a nightly job with CEF cached is owed. Zero-copy D3D11 is not attempted (haktui's rounds: E_INVALIDARG); the pane paints through the CPU path at the 15.6 ms Windows timer floor while scrolling.
3. The rename zeron -> surya lands last (decision 23, `scripts/rename-apply.sh`, PR #41). Until then the binary is still `zeron` and env vars are `ZERON_*`.
4. Pending permissions are lost on engine restart; a deleted chat denies its pending tool (by design).
5. Mac build parked (owner 06:08).
6. `cargo test` on Windows still fails: test-only unix code (source_control.rs tests, 13 files under engine/tests and harness/tests). `cargo build` is clean once PR #43 lands.
7. Never launch Xorg or any long-lived process from inside a `flock` block: the child inherits the lock fd and holds the lock for life (cost 40 min tonight). Use a lock-free shell or `flock -o`.
8. Agent mail ack race (found 11:23 on main's CI): a turn that completes before the engine records its run id loses that mail's ack. Fix PR fix/agent-mail-ack-race; if RC1 ships without it, a lost ack shows in `zeron mail drain` and the mail is not redelivered.
9. Test flakes in comet's own suites seen on CI tonight: harness/tests/claude.rs fixture chmod race (ETXTBSY), harness/tests/acp.rs steering order, engine empty_reasoning_deltas_are_heartbeats under load. Re-run once before believing a red.
